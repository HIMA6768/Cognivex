# Breast Cancer Data / Schema Handoff — Corrected

This bundle is the corrected early data/schema handoff for the METABRIC-based Breast Cancer Prognosis & Subtype Classification project.

## Canonical files

- `METABRIC_RNA_Mutation.csv` — uploaded raw merged dataset, preserved unchanged.
- `METABRIC_prepared.csv` — canonical prepared dataset generated by `prepare_data.py`.
- `manifest.csv` — locked reproducible 70/15/15 patient-level split.
- `patient_mapping.csv` — 1:1 patient/genomic-sample mapping for this merged file.
- `clinical_schema.json` — clinical inputs and survival-target contract.
- `subtype_labels.json` — raw-to-display subtype mapping and NC policy.
- `feature_groups.json` — exact clinical, mRNA, mutation, ID, survival-target, and subtype-target column groups.
- `dataset_summary.json` — cohort counts, real per-feature missingness, event/censoring counts, and split-level event/subtype distributions.
- `dataset_provenance.json` — provenance fields; URL/version/license remain pending confirmation because they were not present in the supplied materials.
- `data_strategy.md` — modeling/splitting/leakage-control policy.
- `prepare_data.py` — reproducible preparation script that regenerates the derived handoff artifacts.

## Important survival coding

The uploaded source uses `overall_survival` as `0=Deceased`, `1=Living`. The prepared dataset converts this to the application/survival-model convention `1=Deceased/Event`, `0=Living/Censored`.

This interpretation was cross-checked against the uploaded `death_from_cancer` field before finalizing the correction.

## Tumor stage policy

- Raw missing values and stage `0` are mapped to categorical `Unknown`.
- Valid stages are represented as categorical strings `1`, `2`, `3`, `4`.
- Other missing clinical values are not globally fitted/imputed in the prepared file; learned preprocessing must be fitted on the training split only.

## Subtype policy

`NC` records remain available for valid survival Tracks A/B, but are excluded locally from Track C molecular-subtype classification.

## Leakage policy

`random_state=42` locks a reproducible split. It does not itself prevent leakage. Leakage control additionally requires unique patient-level partitioning and training-only fitting of imputation, scaling, encoding, filtering, feature selection, and hyperparameter tuning.

## Outstanding provenance blocker

The supplied handoff identifies the dataset as METABRIC via Kaggle but did not include the exact Kaggle URL, dataset version/date, or license. Those fields remain explicitly `null` / `PENDING_CONFIRMATION` rather than being guessed.
